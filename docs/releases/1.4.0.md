# agenthouse engineering 1.4.0

This release adds role and product-process guidance from market discovery and
validation through product delivery, release, support, and learning. Roles point
to skills and optional methods; they do not grant governance authority. Process
guidance helps users select a subprocess or orient from current evidence, while
workflow status remains with the consumer's chosen authority.

- **Role guidance:** list, inspect, and load generic role baselines with
  `roles list`, `roles show`, and `roles use`. Role guidance defines purpose,
  responsibilities, boundaries, decision rights, related processes, skills,
  and optional methods.
- **Product processes:** navigate product lifecycle, market validation, feature
  requests, bugs, changes, releases, and incidents with `process list`,
  `process show`, and `process start`. `process where --description ...` offers
  tentative orientation and asks the user to verify it against the authoritative
  work item or process. It does not create or store workflow state.
- **Consumer-owned global copies:** explicitly adopt baselines to the local
  global repository (by default `~/.agenthouse/global`, configurable with
  `AGENTHOUSE_GLOBAL_REPO`). Adoption preserves pre-existing files and reports
  conflicts. Consumers can edit their copies and keep them in their own local
  repository.
- **Baseline updates:** `roles check` and `process check` compare the adopted
  baseline, consumer edits, and packaged baseline. Merge applies independent
  changes only when there are no overlapping conflicts; ignore records a
  deferred revision. Neither action happens implicitly during framework update.
- **Skill coverage:** role/process views report mapped, available, missing, and
  candidate-gap guidance. Specialist skill instructions remain owned by their
  source projects.
- **Distribution:** the role/process definitions and schemas are included in
  framework packages and offline bundles. Existing project runtime pins remain
  unchanged until the consumer chooses to update them.

## Install and update

```text
npm install --global @agenthouse/engineering@1.4.0 --ignore-scripts
```

After installing or updating the CLI, use a repository-pinned launcher to load
the commands into your current project runtime:

```text
node .agenthouse/run.mjs roles list
node .agenthouse/run.mjs roles use --id product-manager
node .agenthouse/run.mjs process start --id product-lifecycle
node .agenthouse/run.mjs roles adopt
node .agenthouse/run.mjs roles check
```

Inspect the reported baseline changes before merging or deferring a revision.
See [roles and product processes](../roles-and-processes.md) for examples,
update behavior, schemas, and limitations.

## Verification and limits

Local verification: 146 Node tests, including role/process adoption, preservation,
lineage, three-way merge and conflicts, deferral, advisory orientation, and CLI
discovery; generated command skills and release allowlist checks. Browser and
usability checks are run as part of this release verification. GitHub and npm
publication are separate outcomes, and the release workflow repeats cross-platform
checks before publishing.

The baselines are generic starting points, not company policy or a complete
market-research, sales, or marketing playbook. Optional methods are attributed
references. Process orientation is advisory and does not read from or write to a
tracker. Baseline update review applies only to explicitly adopted local copies;
it does not synchronize organizations or alter project runtime pins.
