# agenthouse engineering 1.3.0

This release adds technical feasibility assessment, incoming change review guidance,
evaluation previews and lifecycle-oriented discovery while retaining repository
policy, exact runtime pins and existing shared/private storage behavior.

- **Feasibility:** `ah-assess-tech-feasibility` links an ADR-style proposal, rollout
  scenarios, migration steps, consumers and Mermaid diagrams to a work item.
  The `assessment` helper inventories literal occurrences at an exact commit and
  validates hashed summaries for ready-gate completeness. Literal matches require
  semantic classification; neither the inventory nor the proposal is approval.
- **Incoming reviews:** `ah-review-mr` guides read-only URL intake, ticket import,
  disposable environments and comment drafting. Prose criterion proposals require
  confirmation before mapping. Review reports distinguish open decisions and
  inherited failures; failed required checks never become successful evidence.
- **Evaluation:** `evaluate --list` / `--plan` prints the profile, build and check
  origins without executing checks or writing reports. JSON and HTML results
  identify the configured module, file and rule where known.
- **Discovery and plugins:** help groups everyday skills by lifecycle and accepts
  natural-language goals. Generated skills and legacy projections identify their
  package version. Plugin guidance loads the repository pin; `doctor
  --plugin-version VERSION` reports version mismatches. Existing plugin manifests
  and pinned local marketplace distribution remain available.
- **Specification gate:** optional `lifecycle.verify` settings require red/green
  evidence before `work advance --to verify`. This does not intercept external
  tracker transitions.
- **Compatibility:** retains Git line-ending tolerance for unchanged managed files
  from the post-1.2.0 fix. Updates preserve existing repository storage choices.

## Install and update

```text
npm install --global @agenthouse/engineering@1.3.0 --ignore-scripts
```

Existing repositories retain their exact runtime pin. For repositories tracking
the verified public channel, inspect before activation:

```text
node .agenthouse/run.mjs update --latest --check
node .agenthouse/run.mjs update --latest
node .agenthouse/run.mjs doctor --plugin-version 1.3.0
```

The last option reports the explicitly supplied installed plugin version; omit
it when no plugin is installed. It does not discover host installations itself.
Offline/private consumers can use the reviewed update bundle and their existing
trust mechanism. See [distribution](../distribution.md).

## Verification and limits

Local verification covers 139 automated tests, generated skills, release packaging,
and readable report origins at 390px and 1280px. The release workflow repeats core
tests on Windows, macOS and Linux and runs the browser checks before npm publishing.
GitHub and npm publication are separate outcomes.

Global skill search depends on host registration and remains environment-specific.
The MR workflow uses available provider tools and inspected project environment
recipes; this release does not add built-in GitLab/Jira connectors or an automatic
container recipe runner. Unknown credential capabilities remain unknown. Modified
source overlays cannot masquerade as exact-head evidence. See
[technical feasibility](../technical-feasibility.md),
[incoming review](../review-mr.md) and
[implementation status](../implementation-status.md).
