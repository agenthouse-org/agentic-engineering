# agenthouse engineering 1.2.0

New repositories can choose **shared** or **private** integration during onboarding. Runtime and skills are stored once per exact version in the current user's central store. Shared repositories commit small instruction bridges and project pins; private integration leaves existing agent instructions and the root `.gitignore` untouched. Agents locate the project's pinned skills with `node .agenthouse/run.mjs context`.

Generated test output is classified per repository. Evaluation checks effective Git exclusions and staged files before and after running checks. Source fixtures and approved visual baselines stay eligible for Git. Cleanup requires an explicitly configured disposable path and `housekeep --clean`; ordinary sessions retain evidence. Git ignore blocks now use `#` comments.

Existing enrollments keep their project layout until explicitly migrated with `ah-engineering init --root PATH --central`. Migration preserves consumer files and refuses modified owned files. A project updated to central storage cannot use `rollback` to activate a runtime that predates central storage; restore the earlier installation from its original files and reviewed bundle if needed. Native skill menus still require separate host or plugin registration.

## Consumer setup

Install the CLI once on each machine:

```text
npm install --global @agenthouse/engineering@1.2.0 --ignore-scripts
ah-engineering init --scope user
```

For each new repository, choose one mode and identify that repository's generated test output:

```text
ah-engineering onboard --root PATH --integration shared --agents codex --artifact-paths test-results,coverage --docs skip
ah-engineering onboard --root PATH --integration private --agents codex --docs skip
ah-engineering doctor --root PATH
```

Use `--artifact-paths` only for generated output, never fixtures or baselines. Review `.agenthouse/config.json` and the actual test-tool settings. Existing shared repositories use `init --root PATH --central` after updating the global CLI. Fresh clones run `ah-engineering restore --root PATH` to fetch the exact pinned content from the installed package or reviewed offline bundle. See [central installation](../central-installation.md).

Verification before release: 133 automated tests, package and generated-skill checks, the browser baseline/broken/restored scenario, and upstream usability pass/fail fixtures with screenshots. The release workflow repeats checks on Windows, macOS and Linux before publishing to npm.
