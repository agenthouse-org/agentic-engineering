# agenthouse engineering 1.5.0

This release clarifies how CI pipelines preserve and publish JUnit XML test
reports when the selected platform supports it. The evaluator already writes
`junit.xml`, `result.json`, and `report.html`; pipelines must upload or ingest
those files explicitly. Report visibility supplements the authoritative
evaluation status and never changes it.

- **GitLab CI:** the supplied template declares
  `artifacts:reports:junit` and retains report files with `artifacts:when: always`,
  including after evaluation failure. GitLab can show the report in its pipeline
  and merge-request test views.
- **GitHub Actions:** the supplied template uploads the evaluation report folder,
  including JUnit XML, even if evaluation fails. GitHub workflow artifacts are
  downloadable files; arbitrary JUnit XML is not parsed into a native test-results
  view. A displayed summary needs a separately reviewed reporting action or
  integration.
- **Agent guidance:** `ah-evaluate` checks that the selected platform uploads
  generated JUnit XML on both successful and failed runs. It preserves the
  command's exit status and warns against treating report upload as a passing
  gate.
- **Process guidance:** the product lifecycle delivery output now includes an
  uploaded JUnit or platform-native test report where supported.
- **Report scope:** framework `junit.xml` projects evaluation checks. It does not
  automatically provide per-test-case detail from a project's test runner.
  Configure the project's native JUnit reporter separately when granular test
  cases are needed.

## Install and update

```text
npm install --global @agenthouse/engineering@1.5.0 --ignore-scripts
```

Existing project runtime pins remain unchanged until explicitly updated. Review
the project's CI template and test-runner output path; report generation alone
does not publish a report. See [CLI evaluation and CI/CD integration](../cli-evaluation.md)
and the [evaluation skill](../../skills/ah-evaluate/SKILL.md).

## Verification and limits

Focused checks assert that the GitHub template uploads report artifacts under
`always()`, the GitLab template configures JUnit report ingestion and unconditional
retention, and the evaluation skill preserves the gate result. GitHub platform
artifacts provide download/retention; they do not provide native parsing of
arbitrary JUnit XML. Consumers should review third-party reporting actions under
their normal supply-chain policy.
